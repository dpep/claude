
In `transaction { find(uuid).destroy! }`, the lookup's deferred cache write ran after the destroy's eviction, which left a stale entry. A record's `after_commit` callbacks run before callbacks queued on the transaction itself. The eviction now runs `after_destroy` and queues its cache delete through [`polyid_after_commit`](https://github.com/dpep/polyid/blob/fa6547d/lib/polyid/model.rb#L166), so it runs after the lookup's write. [`polyid_after_commit`](https://github.com/dpep/polyid/blob/fa6547d/lib/polyid/model.rb#L166) moves out of `private` so the instance callback can call it.
